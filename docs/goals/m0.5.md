# NovaGame M0.5 Framework Bootstrap

## Objective

Build the minimum reusable NovaGame kernel required to bootstrap a specific game and prove the configuration path from MySQL-backed operations to a Cocos-compatible SwordMaster smoke consumer.

This is a repository runbook for coding agents and engineers. It is not a Codex desktop active Goal and must not be registered as one unless the user separately requests that action.

## Authority And Required Reading

Before starting or resuming a stage, read:

1. the root `AGENTS.md`;
2. the nearest scoped `AGENTS.md` for every subtree that will change;
3. `docs/architecture.md`;
4. `docs/workflows/development.md`;
5. any workflow named by the stage.

This goal authorized M0.5 work only. With `status: complete`, it is now a verification record and does not authorize M1 or later work.

## Execution Protocol

- Execute stages in order.
- Keep exactly one stage `in_progress` at a time.
- Before editing, update `active_stage`, the stage table, and `updated_at`.
- Mark a stage `complete` only after every listed completion condition and verification command succeeds.
- Record the exact successful commands in the verification log.
- If a prerequisite or required check fails, keep the stage incomplete, set the goal status to `blocked`, and record the blocker and failing command.
- Do not skip a failed stage, weaken an acceptance criterion, replace MySQL verification with an in-memory provider, or replace real server integration with frontend mocks.
- When the blocker is resolved, return the goal to `in_progress` and continue the same stage.
- Mark the goal `complete` only after M05-09 and the final root verification pass.

Allowed goal statuses are `drafting`, `ready`, `in_progress`, `blocked`, and `complete`. Allowed stage statuses are `pending`, `in_progress`, `blocked`, and `complete`.

## External Preconditions

- NovaCore source is available from `NOVACORE_ROOT`, falling back to `D:\Programs\nova-core`.
- `VBEN_TEMPLATE_ROOT` points to a fixed local Vben Admin 5 `web-ele` template.
- .NET 8 SDK, Docker with Compose, Node.js, and the package manager version declared by the Vben template are available.
- A supported Cocos Creator version is available before the manual scene smoke check. Headless TypeScript tests must not depend on opening the editor.
- Local secrets are generated or supplied through ignored environment files, environment variables, or .NET User Secrets. No credentials are committed.

If an external precondition is missing, finish all earlier independent work, then record a blocker at the first stage that requires it.

## Fixed M0.5 Decisions

- Preserve the NovaCore-generated `NovaGame.Host.EntityFrameworkCore` project name.
- Keep the framework-owned `Operations/AdminAccess` and `Content/GameConfig` capabilities inside the six standard business-layer projects and organize them by business domain. Deployment and DbMigrator remain operational composition projects.
- Do not generate physical domain modules or entity-first top-level folders.
- Use MySQL 8.4 through Pomelo. Do not retain a SQLite runtime path.
- Keep EF provider execution-strategy retries disabled while NovaCore owns explicit transactions outside a replay delegate. Transient failures propagate, and retryable commands must be idempotent.
- Use Vben Admin 5 `web-ele`, Vue 3, Element Plus, and TypeScript.
- Implement real administrator authentication and server-side authorization.
- Implement versioned GameConfig as the first complete infrastructure slice.
- Limit SwordMaster to configuration snapshot consumption; do not add gameplay.
- Do not implement or scaffold complete game-owned systems such as Mail, Ranking, Shop, Activity, or gameplay domains.

## M05-04 - Administrator Access

### Actions

- Implement the framework-owned administrator capability under the `Operations/AdminAccess` business domain across the six standard business layers.
- Model administrators, roles, administrator-role membership, role permissions, and refresh-token sessions without creating a physical module.
- Hash passwords with a reviewed ASP.NET Core password hasher.
- Issue 15-minute JWT access tokens with stable subject and name claims.
- Issue opaque 7-day refresh tokens, store only hashes, rotate on every successful refresh, detect reuse, and revoke on logout.
- Deliver the refresh token through a secure HttpOnly cookie and keep access tokens out of URLs and logs.
- Replace NovaCore's null permission checker with a database-backed checker.
- Add authentication and authorization middleware in the correct order.
- Implement:
  - `POST /api/auth/login`;
  - `POST /api/auth/refresh`;
  - `POST /api/auth/logout`;
  - `GET /api/auth/codes`;

- Rate-limit login attempts.
- Seed one administrator and administrator role only when ignored configuration supplies the required credentials and no administrator exists.
- Add migrations and audit records for authentication and permission changes.
