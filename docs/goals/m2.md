## M2-02 Policy And Mechanism Map

### Proven Boundary

| Concern | Input | Output or failure | Owner after extraction |
| --- | --- | --- | --- |
| Snapshot transport | Active environment and configuration-set request | `GameConfigSnapshotDownload` or a GameConfig application failure | SwordMaster application orchestration; the validator has no transport dependency. |
| Neutral snapshot validation | Exact snapshot bytes, a trusted lowercase SHA-256 value, expected configuration set, expected schema, and optional expected configuration version | Immutable verified envelope metadata and exact canonical content, or `false` for untrusted or malformed input | NovaGame `Content/GameConfig`. |
| Equipment content interpretation | Verified canonical content and verified configuration-version identifier | SwordMaster `EquipmentDefinition` values or an invalid game resolution | SwordMaster `PlayerAssets`. |
| Definition lookup | Requested configured item identifier and parsed definition map | Found, missing, or invalid resolution | SwordMaster application policy. |

The neutral validator is independently useful to any .NET game consumer that receives a NovaGame
GameConfig snapshot. It does not know how the bytes arrived or what game collections mean.

### Neutral Mechanism Invariants

| Area | Shared guarantee |
| --- | --- |
| Trusted bytes | Require a 64-character lowercase hexadecimal trusted SHA-256 value and compare it to SHA-256 over the complete, unchanged snapshot byte sequence before parsing. |
| Encoding | Require strict UTF-8, reject a UTF-8 byte-order mark and invalid sequences, and require an exact UTF-8 round trip. |
| JSON document | Require one strict JSON object with no comments, trailing commas, leading or trailing trivia, or duplicate properties. Allow a 65-level whole-snapshot envelope so content accepted at the producer's 64-level limit remains consumable; reject deeper content during neutral content processing. |
| Envelope | Require exactly `formatVersion`, `schemaVersion`, `configurationSet`, `configurationVersion`, `createdAtUtc`, `integrity`, and `content`; require format version `1`; compare configuration set, schema, and optional version to caller-supplied expectations. |
| Identifiers and time | Require a safe configuration-set slug, a nonzero lowercase `D` GUID, and a valid UTC timestamp in the producer's exact seven-fractional-digit `Z` format. |
| Integrity metadata | Require exactly `algorithm`, `canonicalization`, and `contentHash`; require `SHA-256`, `NovaGame.GameConfig.CanonicalJson.v1`, and a lowercase hexadecimal content hash. |
| Canonical content | Hash the exact raw UTF-8 bytes of `content`, require the embedded hash to match, process the neutral GameConfig content contract, and require its canonical output to equal the exact raw content. |
| Result | Return only verified neutral metadata, trusted hashes, and immutable canonical content. Do not return a mutable `JsonDocument` or interpret a game collection. |
| Failure | Return validation failure without leaking parser or cryptographic exceptions. Programmer argument errors are not transport or game-domain errors. |

The completed M1 .NET consumer accepted a wider malformed-input set than the producer and the
independent TypeScript consumer because it used general `Guid` and `DateTime` parsing and did not
independently prove canonical content. The extracted boundary adopts the already published producer
format and the stronger TypeScript consumer invariants. This is a protocol-conformance correction:
every valid snapshot produced by NovaGame remains valid, and no approved M1 happy path or game rule
changes. Transport-specific strong ETag parsing remains in the TypeScript HTTP boundary; adapting a
`GameConfigSnapshotDownload` remains in SwordMaster.

### Smallest Public Contract

The following shape remains experimental after M2. Names and signatures may change with coordinated
consumer migration; the completed extraction does not create a source or binary compatibility
promise.

```csharp
public sealed class GameConfigSnapshotValidator
{
    public bool TryValidate(
        ReadOnlyMemory<byte> snapshotUtf8,
        string trustedSnapshotHash,
        GameConfigSetKey expectedConfigurationSet,
        string expectedSchemaVersion,
        Guid? expectedConfigurationVersionId,
        [NotNullWhen(true)] out ValidatedGameConfigSnapshot? snapshot);
}

public sealed class ValidatedGameConfigSnapshot
{
    public Guid ConfigurationVersionId { get; }
    public GameConfigSetKey ConfigurationSet { get; }
    public string SchemaVersion { get; }
    public DateTime CreatedAtUtc { get; }
    public string SnapshotHash { get; }
    public string ContentHash { get; }
    public string CanonicalContentJson { get; }
}
```

The concrete class is the contract because one deterministic implementation is proven and no
implementation variation justifies an interface. Method parameters keep the boundary smaller than
a one-use request DTO. The implementation does not retain input memory. Returned strings and value
types are immutable, and no mutable JSON document or caller-owned byte buffer is exposed. Strict
UTF-8 round-trip validation makes `CanonicalContentJson` an exact immutable representation of the
hashed raw content bytes. `TryValidate` returns `false` for malformed or untrusted snapshot data.
Null or invalid caller expectations and `Guid.Empty` as an expected version are programmer errors
and throw argument exceptions. No public error-code taxonomy is added because the proven
SwordMaster consumer requires only valid or invalid at this boundary.

### Operational Semantics

- The service is deterministic, synchronous, stateless, CPU-only, and performs no external I/O.
- It owns no aggregate, persistence, migration, transaction, concurrency state, retry,
  idempotency key, authorization decision, audit record, clock, or generated client contract.
- It does not parse ETags, choose an environment, download a snapshot, cache content, activate a
  version, log a game operation, or interpret collection records.
- Cancellation is not part of the minimal contract because no asynchronous or blocking boundary

- A later stable contract must evolve additively where possible; a breaking signature or protocol

## M2-07 Contract Maturity Decision

**Decision:** keep `GameConfigSnapshotValidator` and `ValidatedGameConfigSnapshot` experimental
after M2.

The generalized tests, NovaGame producer use, TypeScript protocol parity, and migrated SwordMaster
consumer prove that the neutral mechanism is independently useful and correctly extracted. They do
not yet prove a stable C# source, binary, package, dependency-injection, or diagnostic contract:

- SwordMaster is the only external .NET game consumer and still uses a same-repository project
  reference. NovaGame Application is a framework self-consumer, and TypeScript validates wire
  semantics rather than the C# API shape.
- The only game consumer maps every validation failure to one game-owned invalid result, so no
  concrete variation proves whether `bool` remains sufficient or typed diagnostics are needed.
- A non-null expected configuration version is covered by neutral tests but not by an independent
  real consumer.
- The TypeScript client intentionally supports schema `1`, while the C# validator accepts a
  caller-supplied valid schema. Current parity evidence therefore does not establish arbitrary-schema
  cross-runtime equivalence.

While experimental, the class names, constructors, `TryValidate` signature, result properties, DI
lifetime, and failure-diagnostic model have no source or binary compatibility promise. Valid
`formatVersion` 1 producer output, SHA-256 integrity, and canonicalization profile v1 remain the
behavioral regression baseline. Changing those wire semantics requires a version or profile change
and coordinated migration of NovaGame, SwordMaster, and the TypeScript consumer. Transport, ETags,
caching, game policy, logging, and error mapping remain caller-owned. Every API change must keep the
generalized tests and SwordMaster consumer passing.

Stable promotion requires additional concrete evidence:

1. a second independent .NET game backend or external consumer with meaningful configuration-set,
   schema, transport, expected-version, or failure-handling variation;
2. consumption through versioned NovaGame Domain packages and a recorded public API compatibility
   baseline rather than only same-repository project references;
3. a real decision on boolean failure versus typed diagnostics and whether the optional expected
   version belongs in the stable shape;
4. a shared producer-generated golden corpus across C# and TypeScript plus an explicit TypeScript
   schema-compatibility policy if broad cross-runtime equivalence is claimed; and
5. memory and latency evidence near the 25,166,848-byte limit before committing to a synchronous
   stable signature.
